## [Unreleased]

### Added

- Tabs for open notes (`src/TabStrip.tsx`, `src/openTabs.ts`) — every note you navigate to opens a tab instead of replacing whatever was open before, so switching between a handful of notes doesn't mean hunting back through the sidebar each time. Deliberately scoped smaller than full VSCode-style tabs: exactly one live collaborative session exists at a time (whichever note is `activePath`), so clicking a tab is just `openNote()` on that path — the same thing clicking a note in the sidebar already did — rather than juggling several concurrent Yjs sessions. Persists across restarts (`localStorage`, capped at 15 open tabs, oldest evicted first), stays visible even while Graph/Table/Flashcards/etc. are showing (clicking a tab returns you to that note's editor), and Cmd/Ctrl+Option+Right/Left cycles between them — the same modifier Safari/Chrome already use for browser-tab cycling on macOS. No "unsaved changes" prompt on close: edits are already continuously synced through Yjs, not a save-on-close model

- Flashcards got the same tile-grid treatment as Canvas/Projects (`src/FlashcardGridView.tsx`) — clicking **Flashcards** in the sidebar used to jump straight into the due-cards review queue, with nothing to look at (and no way to browse what you'd actually made) once nothing was due. Now it opens a grid of every `type: flashcard` note, a "+ New Flashcard" tile top-left same as the others, and a due-count callout ("N cards due for review") with a "Review now" button that hands off to the existing review flow — which now has its own way back to the grid instead of only reaching it by re-clicking the rail nav
- `​```timetable` blocks — a weekly grid (one entry per line: `Day HH:MM-HH:MM Title`), rendered as a CSS Grid week view with entry height proportional to duration. A "Full screen" button opens it sized to the viewport, requests the Fullscreen API, and best-effort holds a screen wake lock (`src/timetable.ts`). Matching styles were added to `export.ts`'s `EXPORT_CSS` so MD/HTML/PDF export renders the grid too
- Reminders: a 🔔 toolbar button sets a `remind_at` date/time on the open note; a native notification (Tauri, via `tauri-plugin-notification`) or browser notification fires when it's due, checked every 20s against the notes list (`src/reminders.ts`, `src/reminderSchedule.ts`). Only fires while Satori is open — not a background/push notification, see README's Roadmap
- Sidebar: Recent/Favorites now only show in the default "All Notes" view — switching to Tutorials/Journal/Canvas/a type filter previously left them sitting above the filtered list, taking up space and making the filter look like it hadn't done anything
- Calendar sync (`.ics`, universal — no OAuth or API keys with any vendor): a `.ics` button on the reminder popup and on every `​```timetable` block downloads a standard iCalendar file Apple/Google/Outlook Calendar all import (`shared/ics.ts`). If you're running the optional server, Settings → Calendar feed also exposes a live, token-gated `GET /api/calendar.ics` URL — subscribe once in any calendar app and it re-fetches on its own schedule, picking up new/changed reminders and timetable entries automatically
- Graph view is interactive now: drag a node to nudge the force layout (neighbors react rather than the one node just relocating), double-click to pin a node in place, scroll to zoom toward the cursor, drag the background to pan, and a "Reset view" button clears pins and returns to the auto-fit framing
- Left sidebar navigation moved into an always-visible rail (icon + label) — Settings and Workspace moved off the note list into the rail's bottom, and Recent moved into its own History view (rail icon) instead of always sitting above the note list
- Journal is a continuous scrollable page now (`JournalView.tsx`), not a filtered note list you click into one day at a time — a bold "Today"/"Yesterday"/weekday heading per entry, most recent first, with that day's content rendered below it; click a heading to open that day for editing, click a link inside an entry to follow it instead
- Project-level sharing: a note made from the new **Project** template (`type: project`, a live `​```query` block listing every note tagged `project: [[Project Title]]`) shares its whole membership under one link instead of one note at a time. New `scope` column on `shares` (`'note'`, the only kind before this, or `'project'`) in both server/db.ts and src-tauri/src/db.rs, kept in lockstep. Fixed a real gap this surfaced: `openNote` used to unconditionally clear the share token on any in-app navigation, on the assumption it always meant the owner — a guest clicking a wikilink inside their one shared note hit this same path and silently lost their session; navigation now only re-resolves role for the new path under the same token instead of discarding it
- A persona/user-type tag: pick "what kind of user you are" (Author, Researcher, Student, Journaler, ...) in the identity panel; shows as a small tag next to "You: name" in the top bar, and clicking it jumps straight to that persona's section of the "Who's this for?" tutorial (`src/identity.ts`'s new `PERSONAS` list, `src/IdentityPanel.tsx`)
- Graph view got a Logseq-style settings panel (opened via a top-right "..." button): Nodes lists every note type present with a live count and a show/hide checkbox, Search dims non-matching nodes, Forces exposes live charge-strength/link-distance sliders wired into the running simulation, and Export (web only) rasterizes the current pan/zoom view to a PNG
- A LogSeq-style block outliner for Journal/daily notes (`src/BlockOutline.tsx`, `src/blockTree.ts`): real indentable, collapsible bullet blocks — Enter for a new block, Tab/Shift+Tab to indent/outdent, Backspace to merge into the previous block, arrow-key navigation between blocks, multi-line paste splits into siblings, click a chevron to collapse/expand. Built the same way `CanvasNote.tsx` already adds Excalidraw content: the block tree serializes to JSON and diff-patches into the same flat Yjs `Y.Text` on a debounce, so no changes were needed to the collaboration protocol, the FTS index, or the Rust/Tauri mirror — a `[[wikilink]]` typed inside a block still gets picked up by the existing link extraction for free. New daily notes seed a one-block outline; a daily note whose body isn't valid block-JSON (existing prose entries) keeps opening as a normal note — nothing already written is migrated. Journal's aggregate feed renders the tree as a nested read-only list instead of raw JSON for entries that use it
- Data dictionary import: **+ Create → Import Data Dictionary…** reads a CSV (one row per column, grouped by table) and creates one `type: db_table` note per table, columns rendered as a markdown table in the body (`shared/csv.ts`, `shared/dataDictionary.ts`). A foreign-key column's `references_table` becomes a real `[[wikilink]]` to the target table's note, so it shows up in Graph view/Backlinks through the existing body-wikilink indexing — no server/db.ts or Rust changes needed. Built directly on the `.bib` importer's precedent (same one-record-one-note shape, same skip-not-overwrite dedup, same Tauri-native-picker vs. browser-`<input>` split)
- Table view rollup columns now support **sum** and **average** over a chosen numeric property on the related notes, not just count/list, and persist across reopening Table view (`localStorage`, same scope as other UI preferences like theme/sidebar width) instead of resetting on remount
- The persona tag now does something: a collapsible **"For you"** sidebar section (above Favorites, same visual pattern) shows 1–2 shortcuts for whichever persona is set — a tutorial-page link and, where one exists, a direct jump to the matching nav view (Journaler → Journal, Student → Flashcards, Planner → Table, Visual thinker → Canvas). Sourced straight from "Who's this for?"'s own curated `→ [[...]]` link per persona (`src/identity.ts`'s new `PERSONA_SHORTCUTS`), not a separate judgment call. Hidden entirely until a persona is set; collapse state persists across reopening
- **Live** editing mode, replacing **Split**: headings, **bold**, *italic*, ~~strikethrough~~, `inline code`, blockquotes, and `- [ ]` task checkboxes now render styled directly in the editor — raw markup hidden except on whichever line the cursor is currently on, where it shows normally so editing stays exact (the LogSeq/Obsidian "live preview" trick). Now the default mode. A new CodeMirror `ViewPlugin` (`src/Editor.tsx`) walks the `@codemirror/lang-markdown` syntax tree per visible range and hides/styles via `Decoration.replace`/`Decoration.mark`; task checkboxes are real interactive `Decoration.widget`s. Toggled via a `Compartment` (reconfigured, not remounted) so switching Source ↔ Live ↔ Preview never loses cursor position or undo history. Source (exact raw text) and Preview (full rendering — Mermaid/math/query blocks/wikilinks, everything Live doesn't cover yet) are unchanged and still available; this is Phase 1 only — wikilink/citation live-rendering and inline diagram/math rendering are deliberately not part of this pass. New direct dependency on `@lezer/markdown` (already present transitively) for GFM strikethrough/task-list parsing
- Project-scoped workspace members: a workspace member can now optionally be restricted to one or more projects, reusing the exact `project: [[X]]` relation project-shares already resolve via `noteBelongsToProject`, rather than the previous all-or-nothing vault-wide access every member had. Zero scoping rows (still the default for every existing member) means nothing changes. New `workspace_member_projects` table and `resolveEffectiveRole` (`server/auth.ts`) — the one place token/session/project-scope resolution now happens, called by both `server/index.ts`'s REST middleware and `server/collab.ts`'s real-time WebSocket handler. Closed a real gap the unification surfaced: the collab WS path previously called `resolveShareRole` directly, bypassing session/scoping entirely, so a project-scoped member could have opened the live-editing socket for any note outside their granted projects. Also makes `noteBelongsToProject`'s matching consistent with every other relation in the app (path-or-title, case-insensitive) instead of a bespoke exact-title-string comparison — a `project:` property can now reference its target by path, not just by title. Admins manage this from the existing Workspace members panel (`src/WorkspacePanel.tsx`): each member row shows their current scopes as removable chips, or "Full vault access" when unscoped, with a "+ Scope to project…" form (project + view/comment/edit role) to add one — new `GET/POST/DELETE /api/auth/members/:userId/projects` routes
- Journal's today entry is live and directly editable in place now, LogSeq-style — no more click-through to a separate editor just to write. Opening Journal (or the "Write today's entry" CTA) points the app's single collab session at today's daily note while staying on the Journal page, and that entry renders the same block outliner the main editor already uses for daily notes (`src/BlockOutline.tsx`) instead of a read-only preview. Past entries are unchanged — still a read-only feed you click through to open, which is also where a pre-existing prose-only "today" note (written before the block outliner existed) falls back to, rather than losing its content to the outliner
- Canvas is a Logseq-style whiteboard tile grid now (`src/CanvasGridView.tsx`), not a filtered note list — every canvas note as a card (title, icon, last-edited date) plus a dashed "+ New Canvas" tile, full-width like Graph/Table/Journal, note-list auto-collapsed the same way those already do. Click a tile to open that canvas in the normal editor; the underlying `type: canvas` filtering this replaces is gone from the sidebar nav's `typeFilter` mechanism entirely — Canvas is a genuine special panel now (`SpecialPanel`), the same transition Journal went through earlier
- Graph view has a real query/filter language now (`src/graphQuery.ts`, a new "Query" section in the settings panel next to Search): `degree > 5` / `>=` / `<` / `<=` / `=` for connection-count filtering, `type: project`, `connected: [[Note]]` for a note's direct neighbors, and `isolated` as shorthand for degree = 0 — one condition per line, ANDed together, and ANDed with plain-text Search too when both are active. A deliberately small vocabulary, not a general expression language — `​```query` blocks (`src/noteQuery.ts`) stay equality-only on purpose, but degree/connectivity aren't note properties a flat filter can express
- **Reminders** got its own sidebar view (`src/RemindersView.tsx`) — every note with a `remind_at` set, soonest-first, past ones dimmed rather than hidden so it doubles as a light history. There was previously no way to see this at all: `remind_at` was purely a per-note property the 20-second due-check loop read silently, with nothing surfacing the full list anywhere
- `​```timetable` blocks (a weekly grid keyed by day-of-week, not a specific date — repeats every week automatically) existed already but had zero discoverability: no template, no menu entry, only reachable by knowing the exact undocumented `Day HH:MM-HH:MM Title` syntax by heart. Added a proper template (`vault/templates/timetable.md`, reachable from **+ Create → New From Template**) with a seeded example week instead of building a parallel feature from scratch
- **New Timetable** is now a direct entry in the **+ Create** dropdown (`onNewTimetable`, looked up by template title since the Timetable template has no `note_type` to key off of like Project's does), not just reachable by digging through the generic New From Template picker — the same discoverability gap the Timetable template itself was added to close (see above), still not actually solved until there was a one-click path to it
- A **Projects** sidebar view (`src/ProjectGridView.tsx`) — every `type: project` note as a tile, plus a "+ New Project" tile that jumps straight to the existing Project template (skipping the generic template picker, since this button already knows what it wants). Same tile-grid shape Canvas already used, now shared via renamed generic CSS classes (`.tile`/`.tile-grid`/`.tile-grid-view`, previously `.canvas-tile`/etc.) instead of copy-pasting canvas-specific-sounding styles for a second, unrelated grid. A project is still a plain note here, not a folder (see `ProjectGridView.tsx`'s own doc comment for why that's staying that way long-term — a note belonging to more than one project at once, a rename not needing to move files, and project-scoped sharing/workspace access already being built entirely on the `project: [[X]]` relation all argue against ever making this folder-backed)

### Changed

- Graph view: node labels were nearly unreadable — a 3px background-colored halo behind 10px `--text-dim` text was thick enough to eat into the glyph strokes themselves at that size, reading as broken/blurry rather than quiet. Now full-contrast `--text`, 11px, weight 500, and a 2px halo. Nodes also got a persistent soft glow (in their own type color), links are a touch bolder/brighter, and the canvas has a subtle radial gradient instead of a flat fill — the previous look read as flat and sparse rather than an intentional "quiet" style. The auto-fit-to-content framing also tightened slightly (less padding) and eases in a bit slower, so settling into the full view reads as a deliberate fit rather than an abrupt zoom-out
- Graph view already had a "This note" scope (the open note's direct connections only, not the whole vault) — it just had no way to reach it from the note itself, only by opening Graph and clicking the toggle by hand. A **Graph** button now sits in the per-note toolbar (and, since Journal's live today-entry never routes through that toolbar, in its own entry header too) that jumps straight to Graph already scoped to whichever note you were just looking at
- Vault switcher and Reindex (top bar, Tauri only) now render as bordered pill buttons instead of flat transparent icons/text — both blended into the bar closely enough that reindexing (the fix for a file existing on disk but not yet in the app's index, since there's no filesystem watcher) was easy to miss entirely
- **+ Create**'s dropdown was getting crowded with two file-import actions that don't belong at the same level as "new note" — Import .bib References… and Import Data Dictionary… moved to a native **File** menu item in the Tauri build (`src-tauri/src/lib.rs`, forwarded to the frontend as `menu:import-bib`/`menu:import-data-dictionary` events); the web build (no native menu bar to move them into) keeps them in the dropdown as before. The **+ Create** button itself collapses to just its icon at narrow sidebar widths now, same `.sidebar.icon-only` treatment the rail nav buttons already had — previously its "Create" label had no such handling and would overflow/overlap once the sidebar was dragged narrow
- New note/canvas/flashcard filenames no longer always end in a giant `Date.now()` millisecond suffix (`my-note-1788432825572.md`) — every note paid for that, whether or not it actually needed disambiguating from anything. Now just the plain slug (`my-note.md`), falling back to `-2`/`-3`/... only if that exact filename is already taken, the same "try the obvious name first" approach any file manager uses. The type suffix (`-canvas-`/`-flashcard-`) is gone too — nothing ever read it back out of the path, `type` already lives in frontmatter. Quick Capture's own separate creation path keeps its timestamp deliberately: its title is auto-derived from the note's first line rather than chosen, so collisions are actually more likely there, and it runs in a separate window with no loaded note list to check against without adding a network round-trip to a flow explicitly built to avoid that
- Calendar view (the month grid) is removed — a date-based view didn't fit what it was actually being asked to do (a recurring weekly routine), which `​```timetable` blocks already cover properly (see above). `src/CalendarView.tsx` and its `.calendar-*` styles removed; calendar *sync* (the `.ics` export/feed — a completely separate feature) is unaffected
- History and Tutorials are collapsible inline sidebar sections now (same chevron/collapse pattern as Favorites/For You), not full-panel destinations you navigate away into — the rail drops from 9 items to 7. Nothing lost: History's data was already capped at 8 entries, and Tutorials' ~13 pages fit the same scrollable compact-list treatment Favorites already had. `HistoryView.tsx` (now unused) removed
- Flashcards' empty state ("no cards due") and the review screen both get a "New Flashcard" button, reusing the exact `+Create → New Flashcard` flow — previously the only way to add one was buried in that menu, with no path to it from the Flashcards view itself
- The rail's icon-only first pass (still icon + no label) was hard to read without hovering and read as too close a copy of VSCode's activity bar — icon + text label now, and switching to a full-panel view (Graph/Table/Calendar/Flashcards/History) auto-collapses the note-list panel instead of leaving two unrelated lists on screen at once
- Vault name/switcher and identity ("You: name") moved out of two full rows at the top of the note-list panel and into the rail's bottom, next to Settings/Workspace — the same kind of occasional, not-per-note action already living there, freeing the space above the search box for the note list itself. Identity is a modal now (SettingsPanel's pattern) instead of an inline accordion
- Reminder popup: `type="datetime-local"` replaced with separate `type="date"`/`type="time"` inputs (the combined widget rendered as a cramped, fiddly segmented editor with no visible calendar) plus quick-pick buttons ("In 1 hour", "Tomorrow, 9am", "Next Monday, 9am"). The 🔔 toolbar button is a real icon (lucide's Bell) now, not an emoji glyph sitting out of step with the rest of the toolbar's icon set

- The rail is drag-to-resize now (140–320px), same handle-and-persistence pattern the note-list and right panels already had (`useResizableWidth`'s `offset` parameter)
- Rail trimmed to three permanent items (All Notes, Journal, Graph) plus a "More" button opening the other six (Canvas, Table, Calendar, Flashcards, History, Tutorials) — nine permanent items was crowded, and a growing feature set means it would only get more crowded over time. Fewer pinned items also meant real room to give each one more padding without widening the rail
- Rethought the whole left column: the rail-plus-note-list split and the "More" overflow menu both drew real complaints (a new panel popping open for six of nine views; nav crowded together at the bottom). Back to one unified, resizable sidebar listing all nine views directly — drag it narrow enough (~130px) and labels drop to icon-only automatically, so the collapse gesture is the resize itself, not a separate mode switched on by something else. Vault name/switcher and identity ("You: name") moved again too, this time into a new persistent top bar (`.app-topbar`) alongside the per-note toolbar (path/status/word count/view mode/reminder/share/delete, moved out of `<main>`) — all "who/where/which note" context lives in one place now, visible in every view, not just while a note happens to be open
- Identity's name field is now explicitly labeled "Name or screen name," with a note that a pseudonym is fine — the field's purpose (attribution on edits/comments, not a legal name) wasn't obvious before
- Search moved into the top bar too, always reachable regardless of which view is active (searching from Graph/Table/etc. now switches back to a list view automatically so the results are actually visible, instead of typing into a box with no visible effect). The type-filter dropdown's "More types…" label — unclear enough that "what does this do?" came up directly — is "Filter by type…" now, with a tooltip explaining it covers anything other than Journal/Canvas (which have their own buttons); it only lists what your vault's notes actually use, so a vault with just one extra type (or none) will show a short list or nothing at all — not a bug, just nothing else to filter by yet
- Journal's visual design: a small uppercase "Journal" page label, a bigger date heading with "Today" picked out in accent color, muted uppercase timestamps, a filled accent "Write today's entry" button, and a hover affordance on each entry now that the whole card is a click target
- `--bg-sidebar` (the left sidebar, top bar, and right panel) sat only a few levels off the main editor panel's background in every theme, barely distinguishable on screen — widened the gap in all four themes, consistently in the same direction (chrome recedes a shade darker/dimmer than the content panel), and fixed solarized-dark, whose sidebar was previously lighter than the main panel instead

### Fixed

- CI's `npm audit --omit=dev` was failing on `fastembed`'s own direct `tar@^6.2.0` pin (several majors behind the `tar@7.5.22` already resolved elsewhere in the tree via `onnxruntime-node`) — overridden past it rather than downgrading fastembed
- The note-list panel's own resize handle computed its width from the mouse's raw screen position, which was only correct back when it sat flush against the window's left edge — once the rail became a permanent fixture to its left, every drag was off by however wide the rail happened to be. `useResizableWidth` now accepts an `offset` for exactly this ("how much space something before me already occupies")
- The rail's new resize handle was invisible to clicks in its outer half — deliberately straddles the rail's edge (`right: -3px`) the same way the note-list panel's own handle does, but the rail also had `overflow-y: auto` for its nav list, which clips a positioned descendant's hit-testable area to the padding box. Moved scrolling to an inner wrapper so the outer element (holding the handle) stays overflow: visible
- The "More" menu had the identical clipping problem the resize handle did, for the same reason — an absolutely-positioned popover inside the same scrolling nav list. Positioned fixed at coordinates computed from the button's own `getBoundingClientRect()` instead, escaping the scroll container entirely rather than trying to stay inside it
- Block outliner: the focus-restore effect was keyed on every block-tree change, so it fired (and reset the cursor to a stale offset) after each keystroke, not just after a deliberate focus move — fast typing landed reversed. Now only an explicit focus-move (Enter/Tab/Backspace-merge/arrow navigation) triggers it
- Creating a note from **any** template (Book/Chapter/Character/Scene) silently stripped its `type` entirely, not just the template's own `type: template` marker — a book made from the Book template never got `type: book`, so its own "Compile chapters" button and its `​```query\ntype: chapter\n...` chapter list never worked, and the same gap would have broken Project's share-scoping the moment `project.md` was made reachable from the picker at all (see below). Templates now declare a separate `note_type` field (e.g. `note_type: book`) that becomes the created note's real `type`, instead of `type` just being deleted
- `templates/project.md` never actually appeared in "+ Create → New From Template" — the picker only lists notes with `type: template`, but the file shipped with `type: project` instead. Fixed alongside the `note_type` change above
- Every note save had been silently failing to update its semantic embedding since the `tar@^7.5.22` override above landed: fastembed's ESM build does `import tar from "tar"`, which throws at module-evaluation time against a real tar@7 ESM module with no default export (fastembed's own dependency range wants tar@6.x's CJS shape) — the override fixed the CVE `npm audit` was flagging but broke fastembed's own import in the process, and every `import("fastembed")` call failed from then on, caught and logged rather than surfaced. fastembed's CJS build isn't affected (TypeScript's `__importDefault` interop already copes with a default-less required module), so `server/embeddings.ts` now loads it via `createRequire` instead of a dynamic `import()`, sidestepping the broken entrypoint without touching the tar version at all. Related Notes/semantic search had been quietly going stale on every edit since — verified live that a fresh note now gets a real embedding and shows up correctly for other notes' Related Notes panel
- Opening Journal points the app's single collab session at today's daily note for live editing (see "Journal's today entry is live" above), but leaving Journal via anything other than opening a specific note — All Notes, Graph, Table, etc. — never reset `activePath` back afterward, so the main panel kept silently showing today's journal entry (often just an empty bullet) instead of whatever note had actually been open before Journal was visited. `showSpecialPanel` now restores it on the way out
- Journal's live today entry looked broken, not Logseq-like: the focused block got a boxy `outline: 1px solid` border around it — a plain form-field look real Logseq editing never has, since a Logseq block gets zero visual chrome while focused, just plain text with a native caret. A first pass swapped the border for a background highlight instead, but that read exactly as boxy for the same reason: any fill on a `flex: 1` textarea spans the row's full width regardless of how subtle the color is. Removed entirely — the active block now blends in completely, matching its read-only siblings. Also wasn't wrapped in the same `.journal-entry-body` container every other entry uses, so it carried its standalone-editor padding/max-width instead and rendered double-indented and misaligned against the rest of the page
- The block outliner (Journal's live entry and the main daily-note editor) always showed a bullet on every line, even a plain flat one with no children — a bullet's real job is signaling hierarchy, so a top-level line that isn't part of one now renders as plain text, no bullet, no indent reservation. Indenting it under something (Tab) or giving it a child brings the bullet straight back, since it's genuinely a list item at that point. Also widened the shared ~760px prose-reading-width convention (Preview, the block outliner, Journal) to 900px — it read as cramped against a normal-sized window
- Journal's chrome, checked directly against real Logseq side by side: dropped the redundant "JOURNAL" eyebrow label above the date heading (no sibling special-panel view — Graph/Table/Calendar/Flashcards — has one either, and Logseq doesn't show one at all, just the date), and removed the blue accent color a previous pass gave "Today"'s heading on the unverified assumption Logseq visually distinguishes the current day that way — it doesn't, every date heading is the same neutral, muted color there. The heading is also noticeably bigger and has more room below it now, matching Logseq's actual scale instead of reading small and cramped by comparison
- `.journal-view`'s widening to 900px (previous entry) never actually took effect: as a direct flex item of `.editor-pane`'s column layout, its `max-width` + `margin: 0 auto` combination collapsed to shrink-to-fit content width instead of filling the container first — auto margins in a flex item's cross axis override `align-items: stretch`, a genuine CSS gotcha `.block-outline` sidesteps by using `flex: 1` (grow) instead. Confirmed via computed styles: it was rendering at ~416px, not 900px. Added an explicit `width: 100%` so it stretches before the cap applies, matching `.block-outline` exactly. That fix also exposed a second, previously-dormant bug it had been masking: the "Write today's entry" button's `width: 100%` rule turned into a giant full-width bar once its container actually got wide — every earlier screenshot of it looking like a normal-sized button was taken while the parent bug kept it narrow by accident. Sized to content instead
- A brand-new Canvas note's near-black appearance in dark mode isn't a bug: dug into Excalidraw's own source and confirmed its dark theme isn't a distinct dark canvas fill, it's a CSS filter (`invert(93%) hue-rotate(180deg)`) applied straight to the `<canvas>` element — a white `viewBackgroundColor` (what every new canvas has always been seeded with) inverts to almost exactly `#121212`, Excalidraw's own documented default dark background, matching how the real Excalidraw app looks everywhere it's embedded. `CanvasNote` still follows the app's own dark/light theme, same as before
- That same near-black canvas still looked visibly off next to the rest of the app's own dark chrome (`--bg-elevated`), even once it was confirmed to be Excalidraw's real default rather than a bug — `#121212` reads flatter and colder than this app's own blue-tinted dark palette sitting right next to it. Solved the filter math directly (same `invert(93%) hue-rotate(180deg)` transform, inverted algebraically) rather than guessing at a color: a new canvas in dark mode now seeds `viewBackgroundColor: #e3e9f7`, which inverts to exactly `--bg-elevated` (`#202531`) instead of Excalidraw's generic default — verified by solving for white's own inversion first and confirming it lands on `#121212` before trusting the rest of the math
- Graph view's force simulation had no damping tuning beyond d3-force's defaults, so a fresh layout's initial charge burst could send weakly-linked nodes drifting outward fast enough that the auto-fit viewBox kept chasing them — reading as "zooms out a lot" with nodes flying off past the edge. Added `velocityDecay(0.55)` (more damping than the 0.4 default) and `alphaDecay(0.04)` (roughly double the ~0.023 default) so the simulation settles into a stable layout in far fewer ticks, verified by sampling the viewBox at several points after opening: it now converges within ~1.5s and stays essentially flat afterward, instead of continuing to grow. Every node's name was already rendering as an SVG label the whole time — it just wasn't legible while the view was busy zooming/resizing out from under it
- The damping fix above calmed the physics but not the framing — the auto-fit still snapped `viewBox` to its newly-computed box instantly, every tick, so on a larger vault the very first fit (jumping from the tight default box to whatever actually fits dozens of nodes) was still a jarring, all-at-once "zoom out," independent of how settled the layout underneath already was. `viewBox` changes past a small threshold now animate (350ms ease-out) instead of snapping; small incremental refits (the common case once things have already settled) still apply immediately rather than triggering a tween for an imperceptible change. User-driven pan/zoom/reset stay instant, cancelling any in-flight auto-fit animation rather than fighting it. Verified by sampling the viewBox through the transition on a 46-node graph: it now grows gradually (800 → 821 → 945 → 1060 → 1081 → 1083 over ~1.8s) instead of jumping straight to its final size

### Added

- Cloud sync now has real, cryptographically enforced view/edit role separation — a passphrase still grants edit access, but a separate view-only content key (derived from the passphrase, not reversible back to it) can be shared instead, and the relay verifies a signature on every write against that room's registered editors before forwarding it, without ever decrypting content to do so. Settings' Cloud sync section gained an Edit/View-only toggle and a "Get a view-only key to share" action; the editor also goes read-only for a view-only session as a UI-level backstop on top of the relay's actual enforcement
- Extensive new tutorial coverage (Team/Workspace, Related Notes/local AI, Settings & export) plus a dedicated **Tutorials** sidebar entry that lists every tutorial page in one place, filtered by tag rather than type
- `server/` can now be deployed to Render (or similar) with one push — a `render.yaml` blueprint, a real `PORT`-aware production start script, and a README section on pointing cloud sync at a deployed relay
- Comments can now be anchored to a specific text range instead of only being a flat per-note thread — select text, click the "💬 Comment" button that appears, and the comment ties to that exact span (a live-highlighted excerpt, clickable to jump back to it). Anchored via a Yjs relative position (`src/yjsAnchor.ts`), not a raw character offset, so it correctly tracks the same text through edits made anywhere else in the document instead of silently drifting onto the wrong words
- `[[Note#Heading]]`/`[[Note#^block-id]]` *links* now scroll to that spot once the note opens, matching what embeds (`![[...]]`) already did — previously the link resolved and navigated correctly but landed at the top of the note
- A new **Calendar** view — a month grid of every note with a date, sourced from the same properties bag Table view reads (daily/journal notes automatically via their ISO-date title, any other note via a `date` property)
- Book/Chapter/Character/Scene templates for long-form fiction and screenwriting (**+ Create → New From Template**) — no new engine, just existing features arranged for the job: a live `​```query` block lists each book's chapters, Table view sorts/filters chapters and scenes, and character relationships are just wikilinks in prose that show up on the Graph automatically. A new tutorial page (`tutorial/writing-books-and-scripts`) walks through it

Misspelled words get a wavy underline; clicking one shows suggestions or lets you add it to the dictionary for the rest of the session

### Fixed

- MD/HTML/PDF export never rendered mermaid diagrams, KaTeX math, `​```query` blocks, or `​```bibliography` blocks — it embedded the raw, unfilled placeholder/fallback markup Preview.tsx's live async passes normally fill in, which export has no equivalent of until now (`renderForExport.ts`, `deferredBlocks.ts`)
- `[@citekey]` citations always rendered as unresolved in every export, even when correct in the live Preview, because `exportEnv()` never built the citations map `Preview.tsx` computes for itself
- PDF export in the native app leaked its own styles onto the entire running UI — a `<style>` tag's rules apply document-wide regardless of its container's visibility, and the export container is left in the DOM permanently. Every export-specific CSS rule is now scoped under `.export-doc`
- A note deleted in the native app while a debounced autosave was still pending could get silently resurrected moments later, since teardown's flush-on-close would write it straight back to disk after deletion — `confirmDelete()` now tears the collab session down deterministically, without flushing, before issuing the delete
- The identity header could get permanently stuck showing "Anonymous" after using email to identify, because the fix only covered new email submissions, not identities already saved in that shape — `getIdentity()` now repairs this on read
- Cloud sync getting stuck on "error" after one failed connection attempt (e.g. a free-tier relay host waking from an idle spin-down) with no way to recover except manually reconnecting — it now retries with capped exponential backoff

- A GitHub Actions release workflow building installers for macOS, Windows, and Linux from a version tag

- Share tokens fail closed: an unresolvable, mismatched, or revoked token is rejected outright rather than silently falling back to full owner access
- Per-note write access (REST and real-time) is checked against the resolving role for that specific note, not just whichever note is currently open
- A native-app content security policy restricting script/style/connection sources to what the app actually needs

- A CRDT state/cache separation bug that could duplicate a note's content if the search-index cache was deleted while a stale client session reconnected
- `window.prompt()`/`window.confirm()` don't work at all in the native app's WebKit runtime — every use was replaced with real in-app dialogs
